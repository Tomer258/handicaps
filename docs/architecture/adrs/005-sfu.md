# ADR 005 — SFU rather than full mesh or server mixing

**Status:** Proposed. **Date:** 2026-10-17.

## Context

Fifteen people may join one room and multiple high-bitrate streams must reach many viewers.

## Alternatives

Full peer-to-peer mesh; SFU forwarding; MCU/server-composited video.

## Decision

Use an SFU with selective subscriptions and measured simulcast. Do not transcode each video on the server.

## Rationale

A full mesh multiplies each sender's upload, while an MCU consumes more server processing and removes independent stream selection. SFU forwarding matches the desired UI.

## Consequences

The VPS bears substantial egress and packet-processing cost. Client decode capacity and available upload remain constraints. Simulcast increases sender work even when it reduces downstream demand.

## Reconsideration triggers

Reconsider MCU-style composition only for a new broadcast/recording product or very weak clients. Revisit topology if room sizes grow well beyond the current assumptions.
