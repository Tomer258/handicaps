# Decisions (user-confirmed or derived) — keep short, append only

- Angular **21** (not 22): system Node is 22.13; Angular 22 needs ≥22.22.3. Do not install Node globally.
- Scope: full app in vertical slices, runnable locally via docker compose. Prod infra templates written, not deployed.

## Derived technical decisions
- Product name: **Hangar** (from design). Dark theme default, light mirror via [data-theme="light"].
- Monorepo per docs/architecture/development-workflow.md: apps/web, apps/api, workers/sound-publisher, workers/asset-validator, contracts, infra, tests, docs.
- Backend: .NET 10 SDK present (10.0.102). Projects: Hangar.Api (host/endpoints/hubs), Hangar.Application (domain + modules in feature folders), Hangar.Infrastructure (EF Core/Npgsql, LiveKit Twirp client, file storage), tests/Hangar.Tests (xUnit).
- Auth: cookie auth (`__Host-hangar` in prod; plain name on http dev), opaque session id in ticket, UserSession row validated each request. ASP.NET Identity password hasher.
- Dev topology: API runs on host (`dotnet run`), Angular `ng serve` with proxy (same-origin /api, /hubs). Postgres + LiveKit + workers in Docker compose (infra/compose.dev.yml). Shared files via bind mount ./.data.
- LiveKit in Docker Desktop: `--node-ip 127.0.0.1`; sound-publisher shares livekit's network namespace (network_mode: service:livekit) so 127.0.0.1 works for both. Fallback: native livekit-server.exe in ./.tools.
- Python workers: Python 3.13 in Docker images.
- LiveKit pinned livekit/livekit-server:v1.9.1 (dev compose, config infra/livekit.dev.yaml, auto_create=false; API creates rooms with 16 slots). Dev keys hangar-dev/… are local-only.
- Lease id = LiveKit identity; participant metadata {"userId"}. Join token grants microphone only; camera/screen sources added per publication reservation (S5) via RoomService UpdateParticipant.
- Roster visibility = lease Active, or Joining after having been confirmed (reconnect grace 45s). Confirmation is server-verified (webhook, POST /voice/{id}/confirm → ListParticipants, or reconciler).
- /internal/livekit/{webhook,admission} live outside /api/v1 (no cookie/CSRF). S8 Caddy: block /internal publicly; forward_auth admission on ALL signaling routes: /rtc, /rtc/v1 (livekit-client 2.23 tries it first, falls back on 404), /rtc/validate.

## S8 production infra (2026-10-18)
- Single-host topology: edge (Caddy), livekit, api, sound-publisher use host networking and talk over 127.0.0.1; postgres published on loopback; asset-validator network none. API uid 10001 = validator uid (shared file store).
- Edge = Caddy 2.11.4 + caddy-l4 v0.1.2 (v0.1.2 requires Caddy ≥2.11.4). :443 layer4: SNI turn.* → TLS terminate → LiveKit TURN 127.0.0.1:5349 (external_tls); everything else → PROXY protocol v2 → Caddy HTTPS server 127.0.0.1:8443. ACME via HTTP-01 on :80 (TLS-ALPN impossible behind layer4).
- rtc.* host: forward_auth (API /internal/livekit/admission) on /rtc and /rtc/* then LiveKit; all else 404. Access logs strip access_token. app.* blocks /internal/*.
- LiveKit v1.9.1 with bind_addresses [127.0.0.1] still binds TURN 5349/tcp on all interfaces (verified) → host firewall must drop 5349.
- appsettings.json is production-safe (SecureCookies true, no connection string); dev values live in appsettings.Development.json. EF CLI needs `-- --environment Development`.
- Production migrations: one-off `--migrate` job (API exits after migrate+bootstrap), never on startup.
- Angular prod build: optimization.styles.inlineCritical=false so CSP script-src 'self' works (no inline onload).
- Backups: pg_dump -Fc + file store + DP keys + manifest → age-encrypted single archive, rclone off-host daily/weekly; restore expires all sessions and voice leases.
- asset-validator caps ffmpeg threads (FFMPEG_THREADS, default 2; -threads per input/output, -filter_threads): with pids_limit 64 + RLIMIT_AS 1 GiB, ffmpeg's per-core thread pools failed on a 16-core host ("Resource temporarily unavailable" → decode_failed). Keep the caps if limits change.
- POC smoke fakes the microphone with a speech-like WAV (--use-file-for-fake-audio-capture): Chrome's default fake beep is a stationary tone that noise suppression removes after a few seconds, making "speaking" checks flaky.
- Authorization watchdog: API ReconcileHealth (complete pass = ListRooms + every room's participants; unhealthy if the last pass was incomplete or no success for 3×ReconcileInterval) → GET /internal/watchdog/reconcile (200/503, loopback only). Admission refuses when stale (no success for 45 s). Host-local workers/auth-watchdog (stdlib Python, uid 10003, dedicated LiveKit key 'watchdog'): 60 s unhealthy/unreachable → flag file /srv/hangar/watchdog/closed (Caddy `file` matcher → 503 on /rtc before forward_auth) + DeleteRoom for all rooms each check; reopens after 30 s healthy. Flag persists across restarts.

- Role hierarchy (S9a): owner unrestricted; others with ManageRoles manage only roles with Position < their highest assigned role, and members whose top role is below theirs (or themselves); nobody may grant (role mask or channel-override allow) bits they do not hold (Administrator holders hold All). Assigning checks only roles that change. New roles: owner → top; others → just below their own top role. Reorder permutes positions among the listed (manageable) roles only. Member removal needs Administrator + hierarchy. Deleting a role deletes its member assignments and channel overrides.
- Audit log (S9d): AuditEvent has no ServerId; an installation is one server, so GET /servers/{id}/audit (ViewAudit) lists all admin events (targets channel/invitation/member/role/server + auth.register). Personal session events (login/logout/revoke/password) are excluded; auth.* details are never returned. Add ServerId to AuditEvent if multi-server ever happens.
- Server mute is stored on ServerMember.VoiceMuted (not only the lease) so leaving/rejoining cannot shed it. Enforced via the LiveKit grant (no microphone source) plus MutePublishedTrack on the live mic.
- Abuse limits (P4a): one chained GlobalLimiter in Api/Infrastructure/RateLimits.cs, partitioned per user id (IP when anonymous). Token buckets (Hangar:RateLimits, burst/perMinute): All /api/v1 300/600, Messages 15/40, Uploads 6/12, Voice 12/30, other Writes 30/60. Excluded from category buckets: /auth/* (own per-IP + per-account throttles), read-position, sound-plays/stop-all (durable DB limits). 429 ProblemDetails code rate_limited + Retry-After/retryAfterMs. Hub: per-connection TokenBucket (30 burst, 240/min) in SessionHubFilter → HubException "rate_limited", connection stays. Tests disable limits except RateLimitTests (own host + DB). Web: throttled message → toast + auto-retry after retryAfterMs with the same clientMessageId.
- Transient PostgreSQL failures (NpgsqlException.IsTransient / SocketException) map to 503 service.unavailable + Retry-After 5 (not 500). Web chat auto-resends a message on 429/503 up to 6 times (same clientMessageId). Voice: an unexpected LiveKit disconnect (not PARTICIPANT_REMOVED/DUPLICATE_IDENTITY) triggers up to 3 quiet rejoins (1.5/4/8 s) with fresh leases before showing "Voice connection lost".
- Disk full (P4c): uploads refused with 507 storage.full when the storage volume has < Hangar:Storage:MinFreeMegabytes (default 1024) free, before writing; ENOSPC/ERROR_DISK_FULL anywhere maps to 507 (logged critical). Interrupted uploads leave no quarantine file or FileAsset row (FileStore deletes partial writes; ASP.NET discards the partial form).
- Ops monitor (P4d): workers/ops-monitor (stdlib Python, uid 10004, host network, state in /srv/hangar/monitor) instead of Prometheus/Grafana. Checks disk/CPU/RAM/traffic (/proc of the host netns), cert expiry (TLS to 127.0.0.1:443 with SNI, DER notAfter), backup age (backups/last-success), /healthz and reconcile → ALERT/STILL BAD (6 h)/RESOLVED to ALERT_WEBHOOK_URL (Discord/Slack JSON, else plain text for ntfy). monitor.env is optional (compose `required: false`); bootstrap creates it for older configs without touching the FILES set.
- Rollback compatibility (P4e): migrations are expand-only (drop/rename/narrow in a later release once no released code uses it). infra/scripts/check-migrations.py (stdlib, CI) fails on Drop*/Rename*/AlterColumn/NOT NULL AddColumn without default/destructive raw SQL in Up(); `// rollback-incompatible: <why>` downgrades to a note (release notes then say rollback = restore backup). Initial is baseline. Drill: 21fcf28 API on latest dev schema passed chat/soundboard/voice-panel/attachments smokes. Missing stored bytes on GET (FileNotFound/DirectoryNotFound) → 404 file.missing (warning log), not 500.
- Pinned inputs (P4f): base images as tag@sha256 index digest (postgres 18.6, python 3.13.16, dotnet sdk 10.0.402/aspnet 10.0.13, node 22.22.0, caddy 2.11.4, livekit v1.9.1, docker 28.5.1-dind). Sound publisher installs requirements.lock (uv pip compile --generate-hashes for x86_64-manylinux_2_28, run inside the pinned python image) with --require-hashes --only-binary=:all:. Debian ffmpeg left unpinned (superseded security builds vanish from the archive). License gate: infra/scripts/license-report.py in CI (NuGet assets + npm lock prod + python dists in image); all permissive as of 2026-10-18. Runbook: docs/runbooks/dependencies.md.
- Security review (P4g, docs/runbooks/security-review.md): login always performs one hash verification (static dummy hash for unknown logins) → no timing enumeration; success path reuses the verification result. LiveKit webhook body capped at 64 KB via IHttpMaxRequestBodySizeFeature before buffering (413). Open before outside invites: admin 2FA + recovery codes (not built), malware scanning only if upload allowlist widens.
- Two-step login (P4h): optional per account; TOTP secret in users.totp_secret encrypted via ISecretProtector (Api: Data Protection purpose Hangar.TotpSecret.v1, so restoring needs the backed-up key ring); users.totp_last_step CAS blocks replay; 10 recovery codes (xxxxx-xxxxx, alphabet without 0/o/1/l/i) stored as SHA-256 hex in users.recovery_code_hashes text[]. Login: /auth/login returns {twoFactorRequired, challenge} (stateless ITimeLimitedDataProtector, 5 min, userId|securityVersion|remember) → /auth/login/code. Failures throttle on key "2fa:<login>" + IP. Login throttle: 5 free per account, 20 per IP (NAT households). QR drawn as one SVG path from qrcode-generator 1.4.4 (allowedCommonJsDependencies). Not enforced for admins (policy in security-review.md).
- Load testing (P4i, docs/runbooks/load-test.md): three separate measurements — iperf3 reverse for provider egress (lk video is ~1.5 Mbps 720p, can't reach the 8 Mbps screen model), infra/scripts/load-test.sh (lk load-test v2.18.8 pinned by digest, layout 5x5 = every subscriber takes every track) for SFU CPU, two real browsers for perceived quality. Host sampler infra/scripts/load-sample.py (p95 CPU ≤75, p95 steal <5, min MemAvailable ≥1.5 GiB). Simulated clients reach signaling through an SSH tunnel to loopback 7880 with a temporary `loadtest` LiveKit key; Hangar:LiveKit:LoadTestRoomPrefix (default empty, refused if it overlaps v_, warns at startup) stops the reconciler from evicting them. Rooms created/deleted by the script (auto_create false).
- UX states (States.dc.html): 06 skeleton rows (.sk/.skrow in design.css, token colours, reduced-motion off) replace the history spinner; 13 CameraProblemDialog in AppShell driven by MediaSessionService.cameraProblem ('missing' for NotFound/Overconstrained, 'busy' for NotReadable) with "Open video settings" (shared openUserSettings(dialog, SettingsSection)); 18 soundboard popover gates on channel PlaySoundboard and names up to two role managers; 15 ghost cards: a remote peer gone from LiveKit but still on the server roster (lease in grace) shows dimmed "Reconnecting…" after 1.5 s for ≤60 s — client-only, relies on pagehide releasing the lease for deliberate tab closes. 02/04/08/09: see the 2026-10-18 entry below.

## 2026-10-18 — UX states 02/04/08/09 interpretations
- 08 "GOING LIVE · 3": no countdown before publishing (it would either delay the stream or claim "not live yet" while frames already flow). The presenter sees "GOING LIVE / Negotiating <quality> with N viewers…" for exactly as long as reservation + publish take; the Go Live dialog closes as soon as the capture is picked.
- 09 buffering: shown on the browser's own `waiting` event, or when no frame arrived for 2 s while either side's LiveKit connection quality is poor/lost (static screens send few frames, so a frame gap alone is not enough). "Dropping to Np" uses the received layer height when it is below the source; the SFU picks the layer (adaptiveStream + dynacast), Hangar only reports it. "Weak connection" = my or the streamer's ConnectionQuality is Poor/Lost.
- 04 "last here" = users.last_online_at, written when the user's last realtime connection goes away (not session LastSeenAt, which only moves on HTTP requests). Shown in the member list, the only place that already has the server's member roster.
- 02 ping cooldown lives in the API process (single replica, like the rest of realtime state); a restart forgets it.
- Responsive: soundboard docking (Concept B) is a per-viewer localStorage preference, only honoured at ≥1280 (Responsive says sm is "always popover"; md unspecified → popover). At lg it hides the member list; at xl both show. Phone (<820): share buttons disabled with "Streaming needs a wider (desktop) window" (a live share can still be stopped); watching shows only the focused stream.
- Invite preview (anonymous, valid secret only) also shows who created the link and the member count: holding a valid secret already authorizes joining, and it tells the friend the link is genuine. Invalid secrets still reveal nothing. The quick Invite dialog keeps the last secret in memory only (never stored) and reuses it while the invite is active.
- Join messages: authored by the new member (MessageKind.MemberJoined, empty body) so they reuse message sequencing, unread, reactions, replies and deletion; posted to the first text channel by position the newcomer can see (no separate 'system channel' setting yet). The owner bootstrap gets none.
